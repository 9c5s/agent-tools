# メモリメンテナンス

Claude Code のプロジェクトメモリ (`~/.claude/projects/<スラッグ>/memory/`) を横断的に保守する。
引数 `$ARGUMENTS` の先頭語でモードを判定する: `lint` / `inventory` / `promote` / `prune`。省略時は `lint` を実行する。
モードに続く引数はそのモードのオプション (プロジェクト名や対象ファイル) として扱う。

## 前提知識

- 各プロジェクトのメモリは「1 ファイル 1 事実」の個別ファイル + 1 行ポインタ index (MEMORY.md) で構成される
- 個別ファイルの正規形式は次のとおり:

```markdown
---
name: <kebab-case スラッグ>
description: <1 行要約。「|」「:」等を含む場合は二重引用符で囲む>
metadata:
  node_type: memory
  type: <user | feedback | project | reference>
  originSessionId: <任意>
---

<本文>
```

- MEMORY.md は「`- [タイトル](file.md) — フック`」形式の行と見出しのみで構成し、知識本文を直書きしない

## lint モード

機械検査を実行してレポートを出力する。

1. 次のコマンドを実行する (スキルのベースディレクトリを `<base>` とする):

```bash
uv run "<base>/scripts/memory_lint.py"
```

- 単一プロジェクトに絞る場合: `--project <スラッグ>`
- 検査項目: index 双方向整合 (E1/E2)、frontmatter の存在と YAML 妥当性 (E3/E4)、正規形式 (E5)、wikilink 解決 (W1)、プロジェクト間の同名ファイル (W2)、MEMORY.md への直書き (W3)、サイズ閾値 (W4)

2. レポートをそのまま提示し、エラーには修正案を添える
3. 修正を依頼されたら、Write / Edit ツールで直接修正する (シェルでの削除は permissions.deny で拒否されるため、削除だけは prune モードを使う)

## inventory モード (棚卸し)

全プロジェクトのメモリを読解し、内容ベースの棚卸しレポートを作る。lint では機械判定できない「何が書いてあるか」「陳腐化していないか」を人が判断できる形にする。

1. まず lint を実行して構造上の問題を把握する
2. `Glob` で全メモリファイルを列挙し、1 体あたり 30 ファイル程度を目安に general-purpose サブエージェントへ分担させる。各エージェントには次を報告させる:
   - ファイルごと: frontmatter の type、description (原文)、本文要旨 (1〜2 文)、陳腐化リスク (特定バージョン、ブランチ状態、日付、ローカルパスへの依存)
   - ディレクトリごと: MEMORY.md との整合性
   - 判断や推奨は書かせず、事実の把握に徹させる
3. 結果を統合し、次の構成でレポートを作成する:
   - 全体サマリ (プロジェクト数、ファイル数、分布)
   - 横断的な所見 (index 不整合、プロジェクト間の重複、形式のばらつき、記述の食い違い、状態依存で陳腐化するメモリ)
   - プロジェクト別詳細
4. レポートはファイルとして保存し、ユーザーに提示する。対応方針の判断はユーザーに委ねる

## promote モード (グローバル昇格)

複数プロジェクトに重複する規範をグローバル CLAUDE.md へ昇格する。

1. inventory 結果 (なければ lint の W2 と feedback 型メモリの description 比較) から、複数プロジェクトで同趣旨の規範を抽出する
2. 昇格候補ごとに次を整理して提示する:
   - 昇格する文言案 (グローバル CLAUDE.md のどのセクションに入れるか)
   - 昇格により用済みになる各プロジェクトのメモリ一覧
   - 昇格せず残すべきプロジェクト固有の例外 (プロジェクト規約が優先される旨)
3. グローバル CLAUDE.md の実体は agent-tools リポジトリの `.claude/CLAUDE.md` (symlink 先) である。承認を得てから branch を切り、適切な粒度で commit する。push と PR 作成はユーザーの指示があるまで行わない
4. ハーネス設定 (settings.json の attribution や permissions.deny) で既に抑制されている規範は CLAUDE.md に書かない。裏取りしてから判断する
5. 昇格が確定したら、用済みメモリの削除を prune モードで提案する

## prune モード (削除)

重複や昇格で用済みになったメモリを削除する。

1. 削除対象の一覧と削除理由を提示し、ユーザーの承認を得る。承認前に削除しない
2. 承認後、次のコマンドで削除する (index 行も同時に除去される):

```bash
uv run "<base>/scripts/memory_lint.py" --prune <ファイルの絶対パス>...
```

3. 削除後に lint を再実行し、index 整合が保たれていることを確認して報告する

## 注意

- メモリファイルの削除をシェルコマンド (`Remove-Item` / `rm`) で行わない。permissions.deny で拒否される
- MEMORY.md は prune の対象にしない (index 行の除去はスクリプトが行う)
- 昇格・削除はいずれもユーザーの明示的な承認を得てから実行する
