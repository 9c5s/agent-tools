# agent-tools

9c5s's skill collection for coding agents.

Claude Code の [プラグインマーケットプレイス](https://code.claude.com/docs/en/plugin-marketplaces) を通じて配布される、個人向け AI コーディングエージェント用スキル集。

## インストール

Claude Code の TUI 上で以下を実行:

```
/plugin marketplace add 9c5s/agent-tools
/plugin install 9c5s@agent-tools
```

インストール後、収録スキルは `9c5s:<スキル名>` の名前空間で自動的にトリガー可能になる。

## 収録スキル

| 名前 | 用途 |
|---|---|
| `codex-review-loop` | Codex に厳密レビューさせ、PASS まで指摘、検証、反映、再レビューの順に繰り返す汎用レビューループ |
| `japanese-tech-writing` | 日本語技術文書の文章規範 (整形、パラグラフライティング、論証の厳密さ、LLM っぽい空句の禁止など) を適用して執筆・推敲する |
| `parallel-dispatch` | 複数スキルを同一対象に対してサブエージェントで並列実行し、結果を統合する |
| `review-resolve` | PR のレビュー指摘 (未解決スレッド、diff 範囲外コメント、bot レビュー) を採用/不採用判定して 👍/👎 リアクション + resolve まで対応する |
| `tdd` | t-wada 式 9 項目チェックでテストコードの品質を分析するレビュー用スキル |

各スキルの詳細は `.agents/skills/<name>/SKILL.md` を参照。

## リポジトリ構成

```
agent-tools/
├── .claude-plugin/marketplace.json   # マーケットプレイス定義
├── .agents/                          # プラグインルート (install 対象)
│   ├── .claude-plugin/plugin.json    # プラグイン定義
│   └── skills/                       # 5スキル
├── .claude/                          # 個人設定 (install 対象外、公開のみ)
│   ├── CLAUDE.md
│   ├── commands/
│   ├── hooks/
│   ├── scripts/
│   └── settings.json
├── tests/                            # hook のテスト
├── biome.json                        # lint とフォーマットの設定
├── tsconfig.json                     # 型チェックの設定
├── package.json
├── README.md
└── LICENSE
```

`.claude/` は作者本人の個人設定であり、`/plugin install` の対象外。GitHub 上では公開されているが、他ユーザーがインストールすることはない。

## 開発

`.claude/` 配下のスクリプトとテストは TypeScript で書く。Biome が lint とフォーマット、tsc が型チェックを担当する。

```
bun install
bun run check      # lint、型チェック、テストを順に実行
bun run lint:fix   # フォーマットと自動修正を適用
```

## Claude Code の応答の言語チェック

`.claude/hooks/ja-style-guard.ts` は PreToolUse に加えて、Stop と MessageDisplay のフックにも登録しています。
アシスタントのテキスト応答を行ごとに判定し、英語の文の行を画面から隠したうえで、日本語での書き直しを求めます。

各フックの役割は次のとおりです。

- **MessageDisplay**：表示する差分から英語の文の行を除き、除いた行数を記録ファイルに書きます。
  記録ファイルの名前には `session_id` と `prompt_id` を含めるため、中断したターンの記録を次の入力に持ち越しません。
  保存される応答とモデルが読む文脈は変わりません。
- **PreToolUse**：記録があれば消費し、exit 2 でツールの呼び出しを差し止めます。
  ターンの途中でも、英語の文の直後のツール呼び出しの時点で書き直しを求めます。
  サブエージェント内の呼び出しでは記録を消費しません。
- **Stop**：記録を消費し、記録か `last_assistant_message` に英語の文があれば `decision: block` で終了を差し止めます。
  書き直しの後（`stop_hook_active` が true の場合）も検査します。
  判定の誤りで終了できなくなるのを防ぐため、差し止めは 1 回の入力につき 2 回までです。

PreToolUse の時点では、直前のテキストがまだ transcript に書き込まれていません。
そのため transcript は読まず、MessageDisplay の記録で判定します。
MessageDisplay と PreToolUse はほぼ同時に起動されるため、MessageDisplay は処理中の印を置いてから処理します。
PreToolUse と Stop は、起動から 120 ミリ秒が過ぎ、かつ処理中の印が消えるまで（最大 0.5 秒）待ってから記録を消費します。
2 秒より古い印は、異常終了した hook の残りとみなして待ちません。

差分と記録は `~/.cache/ja-style-guard` に置き、1 時間を過ぎたものを削除します。
差分を残すのは、差分の境界をまたぐコードブロックの内側を判定するためです。

記録は表示処理ごとに 1 ファイルとし、書き終えてから名前を付け替えて公開します。
消費する側は、公開済みの各ファイルの名前を付け替えて取得してから読むため、並行する消費と同じ記録を二重に数えません。

差し止めの理由には英語の本文を引用せず、書き直しの前置き、謝罪、英語で書いていた旨の説明を書かないよう指示します。
英語を引用する場合は「」かインラインコードで囲むよう案内します。

英語の文は次の規則で判定します。

- コードブロック、インラインコード、引用（`>`）、Markdown のリンク、「」『』と二重引用符の内側、URL、パスは判定から除きます。
  括弧の中の日本語の注記も除きます。全角の括弧と、ひらがなを含むか日本語の文字が英字の半数以上ある半角の括弧が該当します。
  フェンスは開いたときと同じ文字で同じ長さ以上の、後ろに何も書かれていない行で閉じます。
  箇条書きの記号の後に置いたフェンスは、開きフェンスとしてだけ認識します。
  インデントによるコードブロックは、箇条書きの続きの行と区別できないため扱いません。
- ドット、ハイフン、スラッシュ、数字に接する英字の並びは、識別子やファイル名の一部とみなして単語に数えません。
- 日本語の文字数が英字の数の半分以上ある行は、英語の文とみなしません。
- 英語の語句を日本語の文法でつないだ行は、英語の名前を含む日本語の文とみなし、英語の文とみなしません。
  次のどちらかに当たる行が該当します。
  - 助詞だけの並び（と、の、を、に など）が英語の語句をつないでいる
  - `.` `!` `?` で終わらず、ひらがなを含む日本語の語句（の比較、を使います など）で終わる
- ひらがなを 3 字以上含む行は、機能語（the、to、I'll など）が 3 語以上あり、英字がひらがなの 8 倍以上ある場合に限り英語の文とみなします。
- それ以外の行は、次のいずれかに当たれば英語の文とみなします。
  - 機能語が 2 語以上ある
  - 3 語以上で、`.` `!` `?` `:` で終わる
  - 2 語で、`.` `!` `?` で終わる

字面の規則による判定のため、次の英文は見逃します。

- 英単語が 1 語だけの行。`Done.` などが該当し、識別子やラベルと区別できません。
- `.` `!` `?` で終わらず、ひらがなを含む日本語のラベルで終わる英文。`I will select はい` などが該当し、末尾の語句が UI のラベルか日本語の述語かを区別できません。`.` で終われば検出します。
- 英文の途中に、助詞だけの日本語の並びを含む行。日本語の文法を説明する英文などが該当します。

判定の誤りで日本語の行を隠した場合も、差し止めの理由で引用を「」かインラインコードで囲むよう案内するため、モデルは同じ内容を書き直せます。
